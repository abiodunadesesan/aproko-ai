# V1.2+ — Async Ingestion, OCR, and Large Files

## Status

- **State:** Planned (not approved for immediate implementation)
- **Depends on:** Sprint 22/23 sync ingest + hybrid search

## Goal

Handle scanned PDFs, images, and files larger than the 12MB sync limit without blocking upload responses.

## Scope (when approved)

- Async ingestion job queue (Upstash Redis or Railway worker)
- PaddleOCR worker path for scanned PDFs and image sources
- Source status transitions: `uploaded` → `processing` → `ready` | `failed`
- Progress UI in library (polling or SSE)
- PPTX text extraction

## Out of scope

- Desktop companion capture (V2 epic: `docs/02-architecture/03-desktop-companion-v2.md`)
- Detector-evasion writing tools

## Entry criteria

1. Product owner approval
2. Worker runtime decision (Railway vs Vercel Queues)
3. OCR cost/latency SLO documented
4. Architecture update in `docs/08-rag/01-rag-pipeline.md`
